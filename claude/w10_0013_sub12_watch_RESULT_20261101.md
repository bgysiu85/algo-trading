## Design choices (and why)
- **Own small container in the trader project, not an edit of the journal's `alerts` container.** That code is in the Trade Journal repo
  (Journal chat's), and the alerts container cannot see the trader's `var/`. The board text said "existing alerts container"; this keeps the
  recorder alerts untouched and needs no cross-repo commit. The cost: a second Telegram sender (same bot, trader's `.env` values).
- **Dead-man ping is sent every cycle regardless of problems.** Its job is "the NAS / Docker is alive"; problems go to Telegram directly.
- **Portal check counts any reply under 500 as up** (login redirects included), so it needs no auth and cannot be fooled by the OIDC wall.
  Cloudflare errors (530/502), timeouts and refusals are down. Three misses in a row before it speaks.
- **Trader check only 04:10-09:25 New York on weekdays**, from the session lock heartbeat (stale after 120 s, as in CLAUDE.md).
  The Gateway and trader Docker states are not read (no Docker socket); a Gateway failure shows up as a missing or stale lock.
